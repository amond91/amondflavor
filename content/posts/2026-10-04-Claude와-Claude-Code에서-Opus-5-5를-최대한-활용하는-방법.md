## 한 줄 요약

Anthropic(claude.dev 블로그, Addy Osmani)의 Opus 5.5 활용 가이드로, 작업 전체와 완료 조건·멈출 조건을 한 번에 전달하고 "신중하게 생각하라" 류의 문구는 지우라고 권한다. 장기 실행은 CLAUDE.md 중단 규칙·TASKS.md 체크리스트·서브에이전트 분업으로 관리하고, 안전장치에 걸리면 이전 모델로 자동 전환될 수 있다는 점을 알려 준다.

## 핵심

- Opus 5.5는 이전 Opus보다 긴 다단계 작업(큰 저장소 변경을 테스트 통과까지 이어가기 등)에 강하다. 초기 테스터들은 적은 감독으로 수 시간짜리 코딩 작업을 실행했다. 프롬프트에는 완료 조건(예: "모든 엔드포인트가 새 클라이언트를 쓰고, 기존 클라이언트가 삭제되고, 테스트가 통과")과 멈춰서 물을 조건("원인을 설명할 수 없는 테스트 실패일 때만")을 함께 적는다.
- Opus 5.5는 모든 응답 전에 스스로 사고하고 사고량도 스스로 정하므로 "신중하게 생각하라", "단계별로 생각하라" 문구는 프롬프트와 저장된 지침에서 삭제한다. 채팅 제품 테스트에서 이 문구를 지우자 품질 저하 없이 응답이 더 빨리 시작됐다. Claude Code에서는 effort로 사고량을 조절하고, 간단한 질문에는 "바로 답하라"고 쓴다.
- Claude Code 장기 실행에서는 요약만 하거나 "계속할까요?"라고 묻고 멈추는 일이 있다. CLAUDE.md에 "사용자 입력이 필요 없으면 계속 진행하고 상태 보고는 다음 행동과 같은 메시지에 넣으라. 사용자 없이는 진행할 수 없거나 데이터 삭제·강제 푸시·저장소 외부 변경 같은 파괴적 작업 전에만 질문하라"는 규칙을 둔다. 파괴적 명령의 권한 확인은 계속 켜 둬야 한다.
- 큰 작업은 서브에이전트로 나누고(예: services/ 아래 서비스마다 하나씩) 각 보고의 근거를 확인한 뒤 "서비스·영향 여부·근거" 표로 마무리하게 한다. 작업 목록은 TASKS.md에 두면 컨텍스트가 요약돼도 남는다. 끝난 뒤에는 "Blocked on me / Changed / Found" 같은 형식을 지정하고, 사용자 결정이 필요한 항목부터 읽는다.
- 검증은 사람이 보기 전에 diff 리뷰를 시키고(병합을 막을 문제만 파일/줄·이유·재현 방법과 함께), 조사에서는 "확인하지 못한 것과 찾아본 위치"를 표시하게 한다. 차트·스크린샷은 직접 첨부하고, 긴 문서는 수치·날짜·이름의 모순을 검사시키며, 스프레드시트·문서는 개요 대신 완성 파일을 요구한다. 한 초기 테스터는 최저 effort의 Opus 5.5가 높은 effort의 Opus 5보다 버그를 더 많이 찾고 오탐은 적었다고 평가했다.
- Opus 5.5는 Fable 수준의 생물학/사이버 안전장치를 처음 적용한 Opus 모델이다. 메시지가 감지되면 대부분 이전 모델로 전환돼 같은 대화가 그 모델로 이어진다. 파일·검색 결과를 포함한 대화 전체가 검사 대상이다. Claude 앱은 모델 선택기, Claude Code는 /model로 복귀하고 /config로 전환 전 확인 설정을 바꾼다. 내부 추론을 그대로 재현하라는 요청은 감지 범주라서 지워야 한다.
- 그 밖에 디자인 요청에는 "흔한 디자인을 피하라" 대신 제외할 패턴 목록(크림색 배경, 이탤릭 강조 단어, 01/02/03 라벨, 고정폭 라벨, 알약 버튼 등)을 쓰라고 한다. 실행 중에는 후속 메시지를 입력해 요구를 추가할 수 있고, 상호작용형 작업에는 연구 프리뷰인 /fast 모드가 있다(추가 사용량 필요, 토큰당 비용 높음). 긴 대화의 짧은 후속 질문이 느리면 프로젝트 지침에 "이전 답변은 확정된 것으로 취급하라"고 추가하되, 뒤 단계가 앞 단계 오류를 드러낼 수 있는 장기 분석 프로젝트에는 넣지 않는다.

## 자세히

원문은 Playbooks 시리즈의 한 편으로(2026-09-22 게시, 읽는 시간 9분), 요청 방식, Claude Code 장기 실행 조종, 결과 확인, Claude 앱 활용, 안전장치 전환, 속도의 여섯 영역으로 구성된다. 각 항목이 "무엇을 할지 / Opus 5.5에서 왜 중요한지 / 어떻게 할지" 틀로 쓰였고, 복사해 쓸 수 있는 프롬프트 예시가 곁들여져 있다. 끝에는 요청, 장기 실행, 확인, 안전장치 전환 네 묶음의 체크리스트가 있다.

수치가 나오는 근거는 초기 테스터의 평가와 저자 측 내부 테스트 몇 건이 전부다. 예를 들어 "think carefully" 삭제 효과는 채팅 제품에서의 테스트이고, 버그 탐지 비교는 테스터 한 명의 평가다. 벤치마크 수치는 원문에 없다.

안전장치 오탐은 원문도 인정하는 부분이다. 소스 코드의 보안 취약점 찾기와 일상적인 건강·교육 질문은 허용되어야 하며, 정상 작업이 잘못 감지될 수 있어 오탐을 줄이는 조정이 진행 중이라고 한다. 잘못 감지되었다면 Claude Code의 /feedback으로 알린다.

## 왜 골랐나

AI 에이전트 개발 관점에서, 완료 조건·중단 조건 명시, CLAUDE.md 중단 규칙, TASKS.md 체크리스트, 서브에이전트별 근거 검증 같은 장기 실행 에이전트 운용 패턴이 직접 참고가 된다.

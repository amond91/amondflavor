## 한 줄 요약

한국어 실시간 음성 예약 봇을 만들면서 단일 LLM 에이전트·워크플로우·경량 LLM 의도 판별기가 모두 한계를 보이자, 생성형 LLM을 걷어내고 Kiwi 전처리 → 비생성형 판별 모델 jev → 코드 기반 로직 및 ColBERT FAQ 매칭으로 역할을 분리한 파이프라인을 구현해 공유한 글이다.

## 핵심

- 화면 UI가 없는 음성 통화는 1초 남짓한 침묵에도 사용자가 장애를 의심하고, 구어체 노이즈·말실수·변심이 실시간으로 들어온다. 필러("잠시만요...")도 반복되면 피로감을 줘서 결국 빠른 LLM이 필수라는 제약이 있었다.
- 시행착오 3단계: ①프롬프트 하나에 규칙과 Tool Calling을 몰아넣은 단일 LLM 에이전트는 지시 이행이 약하고 환각이 심하며 느렸다. ②워크플로우 도구는 '버튼 대신 목소리로 누르는 ARS'에 가까워 자유 발화에서 한계가 왔다. ③10B급 경량 LLM 의도 판별기는 컨텍스트가 쌓이면 JSON 출력이 깨지고 "내일이나 모레" 같은 다중 선택 추출이 어려웠으며 지연도 요동쳤고, 비즈니스마다 파인튜닝이 필수였다.
- 현재 구조는 [Kiwi 형태소 분석 전처리: 상대적 날짜 표현 변환 및 날짜/시간 후보 추출 → jev: 이전 컨텍스트와 후보를 받아 의도(신규/변경, 후보 부합 여부, 문의 포함 여부)만 판별 → 코드 기반 비즈니스 로직 및 정적 FAQ 매칭]이다. 글에 따르면 jev는 말 바꾸기와 2개 복수 선택까지 상위 LLM 수준으로 잡아내며 300~500ms 내에 판별한다.
- 복수 선택은 추가 질의 대신 슬롯을 배열화하고 DB 잔여석을 확인해 유효한 선택지만 되묻는 흐름("내일은 마감되었고 모레 가능하신데...")으로 처리한다. FAQ는 생성 모델 없이 매장 표준 Q&A를 사전 임베딩해 두고, jev가 문의를 감지하면 경량 ColBERT의 토큰 단위 Late Interaction으로 매칭하여 수십 ms 내에 한 문장에 섞인 복수 문의(주차, 아기 의자)에도 정적 답변을 뽑는다. 전담 LLM에 넘기면 묻지 않은 예약 절차를 지어내는 환각이 있었다고 한다.
- 음성 특화 설계로, 발화를 복창("내일, 10월 21일 수요일 점심 예약이시고요.")과 잔여석 제안으로 쪼개 독립 오디오 스트림으로 송출한다. 복창은 침묵을 메우는 유의미한 필러 역할을 한다. 끼어들기(Barge-in)는 중요도에 따라 달라서, 저중요도 발화는 즉시 폐기하고 슬롯 처리로 넘어가며, 예약 확정·만석 같은 고중요도 발화는 끼어들기 후에도 코드로 강제해 다시 송출한다.
- S2S(Speech-to-Speech) 모델은 지연을 줄였지만 구조상 처음 실패했던 '단일 LLM 에이전트'와 같은 블랙박스이고 음성 토큰 비용도 높다고 본다. 판별 모델과 코드로 상태를 통제하면 추론 비용이 미미해져 운영비가 예측 가능한 STT/TTS 비용으로 수렴한다고 주장한다.
- 결론적으로 비즈니스 정책을 제대로 적용하려면 AI 발화는 기계적이고 다소 단순해질 수밖에 없으며, 프롬프트 가드레일 땜질보다 명확한 코드로 로직을 구현하는 편이 디버깅·검증·유지보수에 더 쉽고 싸다고 말한다.

## 자세히

글쓴이는 AI와 사람 간 실시간 음성 통신 기술을 개발하는 팀이며, '식당 예약처럼 실제 업무를 수행하는 음성 에이전트가 가능한가'라는 질문에서 출발했다. 한국어 전용 라이브 데모(raixact.com)와 Medium 전문 링크를 함께 제공했다.

핵심 설계 원칙은 역할의 철저한 분리다. 추출 능력이 없는 비생성형 판별 모델 jev의 특성에 맞춰, 후보 추출은 가벼운 전처리기(Kiwi)가, 순수 의도 판별은 jev가, 응답과 정책은 코드가 맡는다. Kiwi 계층은 STT 오류와 판별 모델의 한국어 인식 한계 사이의 완충 장치 역할도 한다. 복수 선택 시 단일 선택 질문지 구조상 해당 항목들에 낮은 스코어가 매겨지는데, 이를 추가 LLM 질의가 아니라 DB 잔여석 확인 후 되묻기로 풀었다.

원문에 정량 평가 표나 벤치마크는 없고, 정확도·지연 수치(300~500ms, 수십 ms)는 글쓴이의 테스트 결과 서술이다. jev 모델 자체의 구조·학습 방식은 이 요약 페이지에 설명되어 있지 않다.

## 왜 골랐나

AI 에이전트 개발 관점에서, 단일 LLM 에이전트 대신 판별 모델·코드·정적 검색으로 역할을 분리해 예측 가능성과 비용을 확보하는 설계 사례로 참고할 만하다.

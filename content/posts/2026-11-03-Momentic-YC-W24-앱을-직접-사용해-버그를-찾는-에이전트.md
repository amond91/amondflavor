## 한 줄 요약

Momentic의 AI QA 엔지니어 Mo가 베타를 끝내고 정식 출시됐다. 일반 영어 YAML로 사용자 흐름 테스트를 작성하고, 앱을 직접 사용해 버그를 찾아 재현 단계와 함께 보고하며, 로컬·CI에서 병합·배포 전 필수 검사로 쓸 수 있다.

## 핵심

- Mo는 프롬프트로 앱의 주요 사용자 흐름을 엔드투엔드로 테스트하고 버그를 찾는다. 웹, iOS, Android 앱을 대상으로 하며, 실행 내용을 모든 PR용 회귀 테스트로 바꿔 준다.
- 테스트 단계와 검증 조건은 일반 영어 YAML로 작성해 저장소에서 코드와 함께 검토·버전 관리한다. 코딩 에이전트는 MCP로 테스트를 작성하고 실제 세션에서 확인한 뒤 YAML을 코드 옆에 저장할 수 있다.
- CLI로 로컬 앱을 검사하고 같은 테스트를 CI에서 실행하며, CLI 종료 코드를 병합·배포 전 필수 검사로 활용한다.
- 실패하면 단계별 스크린샷과 실행 추적을 보고 애플리케이션 버그, 테스트 간헐적 실패, 환경 문제로 분류한다. UI가 바뀌면 실행 중 복구로 컨트롤을 다시 찾고, 영구 복구는 테스트 파일 수정안을 제안해 검토 후 적용한다.
- 지식 베이스에 제품 용어·비즈니스 규칙·예상 동작·테스트 지침을 등록하면 AI 단계가 실행 중 관련 항목을 조회한다. 앱 그래프는 실행 중 관찰한 화면과 흐름을 매핑하고, 세션에서 나온 새 지침 제안은 검토 후 추가한다.
- 정식 출시와 함께 기능 버그는 별도 에이전트가 재현한 뒤 보고한다. QA Bench(Gitea, Metabase, Twenty, Saleor의 20개 영역, 영역당 60분)에서 Mo는 라벨이 부여된 버그 약 269개를 찾았고, 다음 에이전트(Codex, Claude Code, Devin 중)는 약 86개였다.
- 고객 사례: Coframe는 병렬 실행으로 6.3배, GPTZero는 테스트 작성·유지보수 3배 빨라졌다고 한다. Quora는 일일 테스트 실행이 7시간에서 30분으로 줄고 수동 테스트 500개 이상을 대체했다. Runway는 110개 프롬프트 평가를 14분에 끝냈다.

## 자세히

Momentic은 코딩 에이전트 덕분에 코드 작성 속도는 빨라졌지만 의도대로 동작하는지 확인하는 일이 병목이 됐다고 본다. 그래서 검증을 에이전트 작업 루프 안에 넣고, 앱 자체에서 얻은 증거로 변경 사항을 확인하는 플랫폼을 내세운다. 성공한 AI 동작은 재사용(캐시)되고, 앱 변경에 따른 수정 제안은 사람이 검토한다.

공개된 버그 사례로는 핀테크 앱에서 로그인 라우팅 변경이 새 기기 2FA 검증을 건너뛴 건, 음식 배달 서비스에서 결제 폼 리팩터링으로 저장된 카드 자동 입력이 사라진 건(배포 8분 전 발견), 여행 서비스에서 다구간 프로모션 코드가 마지막 결제 단계에서 거부된 건이 있다. 모바일 키보드 자동 닫힘, iOS 잠금 시 수면 타이머 초기화, 차량 호출 앱의 ETA 구독 실패, 검색 2페이지 이동 시 필터 초기화, 스트리밍 서비스의 자막 언어 오류, 레거시 API 버그 12개를 하루에 찾은 사례도 있다. 홈페이지는 지금까지 잡은 버그를 117,010건으로 집계한다.

변경 로그에 따르면 Mo는 PR 댓글·라벨·CLI로 시작해 PR의 프리뷰 배포를 테스트하고 리뷰와 커밋 체크를 남긴다. 세션 노력 수준은 low~max로 고르며, PR 하나에 약 15분부터 앱 전체에 약 2시간까지다. 회사는 SOC 2 Type 2 인증, SSO·RBAC, 계약상 가동률 SLA를 내세운다. 다만 QA Bench 수치와 고객 성과는 모두 Momentic 자체 게시 자료이며, 벤치마크 방법론의 세부는 이 원문에 없다.

## 왜 골랐나

AI 에이전트 개발 관심사와 맞닿는다. 코딩 에이전트 루프에 MCP로 검증 단계를 넣고, 지식 베이스로 에이전트에 도메인 맥락을 주며, 사람이 수정안을 검토하는 구조가 에이전트 설계 참고가 될 수 있다.

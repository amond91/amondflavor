## 한 줄 요약

Windows 11의 MissionControlAggregator.dll이 실행 파일 이름만으로 코딩 에이전트(codex.exe, claude.exe 등)와 개발 도구 사용 여부를 감지해 비트맵 진단 보고서(Segments.SubCohorts)로 만들고, '선택적 진단 데이터'가 허용돼 있으면 Microsoft 전송 대기열에 넣는다는 리버스 엔지니어링 결과이다.

## 핵심

- MissionControlAggregator.dll은 CLI 에이전트 4개(copilot.exe, claude.exe, codex.exe, agy.exe)와 데스크톱 에이전트 5개(github.exe, claude.exe, codex.exe, cursor.exe, antigravity.exe)를 실행 파일 이름으로 검사한다. 기능 이름은 CLICodingAgentUsage(기능 ID 62580080)이다.
- node.exe, python.exe, dotnet.exe, gcc.exe, clang.exe, gdb.exe, javac.exe, devenv.exe, code.exe 등 일반 개발 도구도 검사하며, 결과는 12개의 넓은 범주로 집계된다. 일부 슬롯은 게시자도 확인한다(Node.js Foundation, Python Software Foundation, Microsoft Corporation). GCC·Clang이 속한 컴파일러/디버거 그룹은 게시자 검사가 없다.
- 프로세스를 직접 스캔하지 않고 기존 이벤트(KernelProcess.AppStateChangeSummary, Win32kTraceLogging.AppInteractivitySummary, WSL의 Lxss.Manager.Exec/ExecCritical)를 구독해 이름을 비교한다. 일반 Windows의 codex.exe도 감지되므로 WSL에만 한정되지 않는다.
- 보고서는 ReportCohorts<12,4,5>가 만드는 비트 집합이며, 실행 시간·포커스 시간·상호작용 횟수 등은 버리고 관찰 여부만 기록하는 것으로 보인다. 조사한 보고서에서 프롬프트나 소스 코드는 발견되지 않았다. 타임스탬프는 개별 사용 시간이 아니라 수집 기간을 나타낸다.
- cmd.exe를 codex.exe로 복사해 실행하자 이름만으로 Codex로 인식됐다(CliAgentSubCohorts: 4 = 1<<2). gcc.exe로 복사하면 개발 도구 슬롯 3이 설정되고 SubCohorts: [8]이 전송 대기열에 들어갔다. 집계 상태는 C:\ProgramData\Microsoft\Diagnosis\AggregatorStorage\MissionControlAggregator$에 저장된다.
- 이 보고서는 privacy.isRequired: false, 즉 선택적 진단 데이터로 처리된다. 테스트한 미국 지역 Windows 11 Home ARM64 신규 설치에서는 이 설정이 기본으로 켜져 있었다(AllowTelemetry=3). 설정 → 개인정보 및 보안 → 진단 및 피드백에서 '선택적 진단 데이터 보내기'를 끄면 거부할 수 있다.
- 모든 설치에서 활성화된 것은 아니다. Parallels의 Windows 11 ARM64 VM(빌드 26200.9974)에서는 서비스 실험으로 이미 켜져 있었지만, 공개 ISO 기반 기본 VM에서는 이미지 기본값상 꺼져 있었다.

## 자세히

저자는 AI로 최신 Windows 바이너리의 문서화되지 않은 기능을 조사하다가 MissionControlAggregator.dll에서 에이전트·개발 도구의 실행 파일 이름 목록을 발견했다. Binary Ninja로 참조를 추적해 이 이름들이 실제 이름 비교 함수에 쓰인다는 것을 확인했다. DiagTrack(Connected User Experiences and Telemetry) 서비스가 별도의 AggregatorHost.exe를 띄우고, 이 프로세스가 DLL을 로드한다. 부모·자식 프로세스 ID와 모듈 목록으로 이를 확인했다.

전송 여부는 ETW 이벤트만으로 입증되지 않는다고 보고 두 가지를 더 확인했다. 하나는 VM의 Diagtrack-Listener 세션이 입력 이벤트와 집계 보고서를 모두 구독하고 있다는 점이다. 다른 하나는 DiagTrack의 EventStore.db AsimovEvents 테이블에서 압축을 푼 JSON 배치에 해당 이벤트가 있다는 점이다. 보고 주기는 약 하루이며, 저자는 수집 기간 시작점을 25시간 전으로 옮기고 DiagTrack을 재시작해 보고서를 즉시 포착했다.

저자는 프롬프트나 소스 코드가 없더라도 어떤 에이전트와 개발 도구를 쓰는지 자체가 상당한 개인정보 문제라고 본다. 기본 활성화 여부는 적어도 테스트한 미국 지역 설치에서 확인한 결과이며, 다른 지역이나 에디션까지 일반화되지는 않는다.

## 왜 골랐나

AI 에이전트 개발 관점에서는 OS 수준에서 에이전트 도구 채택률이 텔레메트리로 집계될 수 있다는 사례이다. 기술경영·기술정책 연구 관점에서는 플랫폼 사업자의 개발자 도구 사용 데이터 수집과 옵트아웃 기본값 설계가 개인정보·경쟁 이슈와 맞닿는다.

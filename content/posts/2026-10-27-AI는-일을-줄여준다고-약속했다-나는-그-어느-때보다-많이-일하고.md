## 한 줄 요약

Bold.org 기술 부문 VP인 필자는 모든 엔지니어링 업무에 AI 에이전트를 쓰면서 구현 비용이 낮아져 스스로 맡는 업무량이 늘었고, 병렬 에이전트와의 맥락 전환 때문에 예전보다 더 많이, 더 무겁게 일하고 있다고 GitHub 기여 기록으로 보여준다.

## 핵심

- 여러 에이전트를 병렬로 돌리면 각 에이전트가 간헐적으로 질문, 계획 승인, 변경 내역 검토, 결과 해석을 요구한다. 그때마다 다른 문제·저장소·의사결정 맥락을 다시 떠올려야 해서 개별 작업의 난도보다 동시에 다루는 문제의 수가 정신적 부담을 키운다.
- GitHub 기여 수는 Full Stack Engineer 시절 월평균 173건, Principal Engineer 시절(2022년 8월~2025년 7월) 114건, VP 초기(2025년 8~12월) 111건이었고, 2025년 12월은 50건으로 입사 후 가장 조용한 달이었다. 기능 개발 비중이 줄면서 활동량도 감소했다.
- 2026년에는 10월 27일까지 2,102건으로 2021~2025년 어느 해의 연간 합계보다 많다(2020년 같은 기간은 2,371건). 8월 427건은 전체 기록의 월간 최고치이며 이전 최고는 2020년 4월의 319건이다.
- 평일 기여 수 중앙값은 2022~2025년 3~4건에서 2026년 7건으로 올랐다. 기여 없는 평일은 18일(기존 연 40~46일)이고, 하루 24건 이상인 날은 16일(기존 연 1일)이다. 공개 기여는 191건으로 전체의 10% 미만이다.
- 1월 이후 '새 모델·작업 방식 → 아이디어 폭발 → 에이전트 증식 → 검토·맥락 전환 누적 → AI 피로로 후퇴'라는 집중 활동과 소진의 주기를 세 차례 겪었다(1~2월, 4월, 8~9월).
- 집중 활동 사이의 조용한 시기도 기준선이 올랐다. 3월은 203건으로 Principal Engineer 월평균 114건을 크게 웃돌았다. 다만 6월 77건처럼 예전과 비슷한 달도 있었다.
- 구현 역량이 아이디어를 생각하고 판단하는 역량보다 훨씬 빠르게 커졌고, 필자는 아직 균형을 찾지 못했다. '더 할 수 있음'이 계속 '더 많이 일함'으로 이어져 피로가 남는다.

## 자세히

필자는 도구 자체를 비판하는 것이 아니라고 밝힌다. 2년 전이라면 시작할 가치가 없었을 조사와 구현도 이제 할 수 있다는 점은 긍정적으로 본다. 문제는 일의 양이다. 예전에는 한 주에 큰 작업 두세 개를 하나씩 집중해 끝냈다. 지금은 구현, 프로덕션 문제 조사, 리뷰, 향후 필요한 연구를 여러 에이전트에 동시에 맡기고, 각각이 '가끔' 필자를 필요로 한다.

데이터는 2019년 1월부터 2026년 10월 27일까지의 월별 GitHub 기여 기록이다. 비공개 작업을 포함한 커밋·PR·리뷰·이슈가 섞여 있어 활동의 대략적 신호일 뿐 가치나 노동시간의 측정치가 아니다. 이전 직장이 자체 호스팅 GitLab을 썼으므로 2019년은 불완전한 기준선이다. 역할상 기능 개발이 적어야 하는데도 2026년 기록이 코딩이 주업무였던 시절 수준으로 돌아왔다는 점이 핵심 관찰이다.

필자는 원인을 '일을 빨리 끝내게 된 것'이 아니라 '착수할 가치가 있다고 느끼는 일의 범위가 커진 것'으로 해석한다. 이전에는 놔뒀을 버그 수정, 코드베이스 전반의 패턴 개선, 신규 프로젝트, 아이디어 구현을 모두 맡게 됐고, 구현이 싸서 여러 아이디어를 동시에 추진하는 데 자연스러운 제동이 사라졌다고 설명한다. 글 말미에 AI가 GitHub 데이터 분석, 차트 제작, 초안 작성을 도왔으며 경험·결정·의견은 필자의 것이라고 밝혔다.

## 왜 골랐나

AI 에이전트 개발 및 활용과 직접 맞닿는다. 에이전트 병렬 운용에서 사람의 검토·승인이 병목이자 인지 부하가 된다는 점은 에이전트 워크플로 설계(개입 빈도, 승인 지점)를 고민할 때 참고할 만하다. 기술경영 관점에서는 구현 비용 하락이 생산성 향상이 아니라 업무량 확대로 이어질 수 있다는 사례다. 다만 단일 개인의 GitHub 기여 수에 기반한 관찰이다.

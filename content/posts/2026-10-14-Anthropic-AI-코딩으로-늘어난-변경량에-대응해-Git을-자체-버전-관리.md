## 한 줄 요약

Anthropic은 AI 코딩(Claude)으로 하루 병합량이 10배 이상 늘어 소스 관리가 병목이 되자, 서버 중심의 자체 버전 관리 시스템 Scion을 개발해 5개월 만에 모노레포를 Git에서 이전했다. 내부 측정에서 체크아웃·최신 코드 가져오기 등이 크게 빨라지고 인프라 CPU·메모리 요구량은 기존 Git 미러 대비 200분의 1로 줄었다.

## 핵심

- 하루 병합량은 2026년 5월 평균 약 2,500건에서 9월 3만 건 이상으로 늘었고, 코드 작성보다 소스 관리·빌드·CI 같은 사람 규모용 개발 인프라가 병목이 되었다. Anthropic은 이 증가세가 당분간 이어질 것으로 본다.
- 모노레포는 main 이력만 약 100GB, 압축된 작업 사본이 25GB 이상이며 CI에서만 하루 약 2,500만 회 체크아웃한다. 단순하게 가져오면 하루 Git 트래픽이 600PB를 넘고, 피크 때는 내부 Git 미러를 수백 개 운영했다.
- Scion은 클라이언트가 항상 온라인이라고 가정한다. 커밋·병합·리베이스·blame 같은 일을 서버가 처리하고 모든 소스 관리 기능을 API로 제공하며, 작업 사본은 선택 사항이고 기본적으로 희소(sparse)하다. 구성 요소는 모두 수평 확장되고 packfile이 없어 저장소 유지보수가 필요 없다.
- 작업 단위인 changeset은 서버에서 생성되는 선행 기록 로그 항목으로, 첫 번째 부모 대비 변경 파일 목록과 콘텐츠 주소를 저장한다. blame·경로 이력·스킵 리스트 같은 파생 데이터는 부모 값에서 재귀적으로 계산하며, 클라이언트를 바꾸지 않고 서버 내부를 최적화할 수 있다. ref 변경은 Spanner 단일 행의 compare-and-swap으로 처리한다.
- 배포는 scion-daemon(노드 로컬 캐시) → scion-cache(리전 캐시) → scion-servers(원본) 3계층이고 각 계층 캐시 적중률은 99% 이상이다. 계층 순서를 엄격히 유지해 리전 캐시 장애가 전체 장애로 번지는 것을 막는다.
- 내부 측정 중앙값으로 에이전트의 새 작업 트리 생성은 7.1분에서 5.1초, 변경 요청당 전체 소스 관리 시간은 34분에서 3.7분으로 줄었다. CI 체크아웃은 31초에서 3.5초로 줄었고, CI만으로 CPU 여력이 25% 개선됐다. 일반 Git 저장소 성능으로 확대 해석할 수는 없다.
- 7명 팀이 Scion, 코드 리뷰 도구 Antique 등 약 6개 관련 시스템을 5개월 만에 만들어 이전했다. 초기 Claude Mythos Preview에 Git-to-Scion 수집 파이프라인을 다시 쓰게 하자 메모리 20분의 1, 속도 4배가 되었다. 엔지니어는 Claude에게 "안 된다"고 말하는 판단과 설계 절충을 맡았고, 모든 변경 요청을 검토하되 줄 단위보다 변경 의도에 집중했다.
- Scion은 초대형 모노레포 전용이라 일반 Git 대체재가 아니며 공개 버전도 만들지 않는다. 대신 서버 확장 구조, 표준화 가능한 서버 측 RPC, 객체 전송·협상 프로토콜, 희소 체크아웃·얕은 복제 개선 등 설계 경험을 GitHub, GitLab, 오픈소스 커뮤니티와 공유하겠다고 한다.

## 자세히

Anthropic은 Git이 분산·오프라인 작업에 맞춘 설계인데, 실제로는 하나의 권위 있는 원본을 두고 대부분의 클라이언트가 항상 온라인인 에이전트와 작업이라는 점에서 간극이 생겼다고 진단한다. 얕은 복제, 희소 체크아웃, 부분 복제, 내부 미러, 스냅샷(seed)을 모두 썼지만, 병합 속도가 오를수록 스냅샷이 main에서 더 뒤처지고 부분 복제에서 diff·blame 같은 이력 기반 작업을 유지하는 부담이 커졌다고 한다. 설계에는 Google Piper와 Meta Sapling의 선행 경험을 참고했다.

체크아웃 프로토콜도 Git과 다르다. scn 클라이언트는 자신이 가진 객체를 서버에 알리지 않고, 루트 트리부터 로컬에 없는 하위 트리와 파일 내용만 재귀적으로 요청한다. 객체가 콘텐츠 주소로 식별되어 불변이므로 어느 캐시든 서버 간 확인 없이 응답할 수 있고, 거대한 단일 packfile 응답이 없어 중단 후 재개도 가능하다. 리전 캐시는 데몬이 쓰는 디스크 형식 그대로 메모리에서 전송하므로 누락 객체 계산이나 델타 압축이 필요 없다.

운영·품질 면에서는 외부 의존성을 차단한 시뮬레이션, 퍼징, 요청 속도 제한을 구축했다. 디렉터리별 권한과, 주석만 바꾸는 변경과 민감한 로직 변경을 구분하는 승인 조건도 지원한다. Claude Tag 기반 "superfan" 에이전트가 scion-daemon, scion-cache, Antique 병합 대기열을 구성 요소별로 감시한다. 테스트 중에도 수백~수천 개 변경이 병합될 수 있어, 저장소 전체를 잠그는 병합 대기열 대신 병합 후·배포 전 자동 테스트에 투자했다고 한다. 원문 기사 본문은 보안 항목 중간에서 잘려 있어 이후 내용은 GeekNews 요약에 의존했다.

## 왜 골랐나

AI 에이전트 개발 관점에서, 에이전트를 항상 온라인인 클라이언트로 보고 인프라를 재설계한 사례이자 AI 코딩이 병목을 개발 인프라로 옮긴다는 증거로 읽힌다. 엔지니어의 역할이 '의도·제약 검토와 거절'로 바뀐다는 서술은 기술경영 관점에서도 볼 만하다.

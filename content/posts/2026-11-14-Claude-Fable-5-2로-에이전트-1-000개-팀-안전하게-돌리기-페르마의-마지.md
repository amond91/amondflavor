## 한 줄 요약

Anthropic 연구진이 출시 전 Claude Fable 5.2 에이전트 1,000개(리드 1 + 헬퍼 999)로 페르마의 마지막 정리를 Lean으로 28.7시간 만에 다시 형식화했다. 9월 실험 대비 출력 토큰은 1/3, 증명 길이는 1/7이었고, Prove2Me나 연구자의 지휘 없이 Git과 공유 Postgres만으로 조율했으며 샌드박스와 모니터가 안전 경계 역할을 했다.

## 핵심

- 9월 실험은 연구자 1명과 에이전트 수십 개가 Prove2Me 플랫폼으로 11일, 약 60억 출력 토큰, Lean 1,300만 줄을 썼다. 이번엔 Prove2Me와 연구자 지휘 없이 28.7시간이 걸렸고, 출력 토큰은 1/3, 증명 길이는 1/7이다. 저자들은 이를 '장난감 실험'이라 부른다.
- 에이전트에게 준 것은 60개 명제 목록, 고전적 증명 경로 한 문장 스케치, 정의, 이전 형식화에서 가져온 증명된 보조정리 47개, 리드/헬퍼 역할뿐이었다. 도구는 셸·파일 편집기, Lean+Mathlib, 자기 Git 브랜치(main으로 merge request), 공유 Postgres였다.
- 리드는 첫 10분 안에 Announce / Assign / Notes / Subtasks / Landed 다섯 개 표를 만들고, 명제마다 헬퍼 16~17명 crew를 배정하고 captain을 뒀다. 헬퍼들은 먼저 난이도 판정을 notes에 올렸고, 47개 명제가 예산 내 불가능하다는 판정이 많았다. 리드는 10개에 헬퍼를 몰아 약 70분 안에 모두 증명했고, 이후 처음 제외했던 어려운 명제들로 재배치했다.
- 3시간 무렵 리드가 'do not wait for me'라고 해서 자유 헬퍼가 직접 일을 집어 가게 됐다. 5.6시간 시점엔 헬퍼 73명이 task 756개를 썼고 그중 captain은 16명뿐이었다.
- 마지막 남은 Langlands–Tunnell은 captain이 0.7~100만 줄 규모에 성공 확률 1% 미만으로 추정했던 명제다. 약 750 헬퍼를 투입했고 task 트리가 10개 영역에서 최대 10단계, 2,418개 작업으로 자랐다. 28.4시간에 이 명제가, 28.7시간에 최종 정리가 증명됐다.
- 안전 설계는 세 겹이다. 에이전트별 경량 VM(네트워크 없음, 게이트웨이 파이프만 연결, 요청에 게이트웨이가 신원 태깅, 락다운 커널, sudo 제거, 비특권 사용자), SQL 구문당 5초 제한과 256 MiB 쓰기 한도, 실행 전 LLM 분류기(실시간 모니터)와 오프라인 모니터다. 분류기가 차단하면 팀 전체가 멈추고 사람이 검토한다. 100만 건 넘는 도구 호출 중 차단 기준에 걸린 것은 없었다.
- 실패·한계 기록: 공유 머신 한 대는 약 100 에이전트에서 메모리·디스크·CPU가 바닥나 100-에이전트 실행의 절반 넘게 중단·재시작됐다. 리드가 일찍 멈추지 않도록 남은 시간 알림을 19번 보냈다. 헬퍼들은 난이도를 잘못 판단했고, 저자들은 이런 때 사람의 격려가 유효할 수 있다고 본다.

## 자세히

이번 실험은 조율 구조를 에이전트가 스스로 설계하게 했다는 점이 핵심이다. 지시된 것은 리드 1명과 헬퍼 999명이라는 계층뿐이었고, 표 설계, 역할 배정, 팀 구성, 작업 트리 분할은 리드와 헬퍼들이 직접 했다. 저자들은 SQL을 고른 이유로 범용 정보 조직 primitive, 1,000 에이전트의 동시 쓰기를 다루는 트랜잭션, Claude의 SQL 친숙성을 들었다. 9월 원 실험에서는 에이전트가 프로젝트 상태를 놓쳐 초기 시도가 실패했고, Prove2Me가 이를 해결했다고 한다.

안전 측면에서 저자들은 단일 방어층으로는 에이전트 팀을 가둘 수 없다고 하며 샌드박싱, 실시간 모니터링, 오프라인 모니터링을 겹쳤다. 이번 실행에서는 action 기반 모니터만 썼고, 실행 직후 CoT 및 에이전트 간 통신을 보는 모니터를 병행 추가했다. 분해 공격(decomposition attack) 등 red-team 평가에서 CoT 모니터는 모든 sabotage 시도를 탐지했다고 한다. 현재 기준으로 로그를 재생했을 때 root 접근 확인 한 건만 차단에 근접했다. 이런 실험은 출시 전 정렬 평가를 마치지 않았을 수 있는 모델로 하므로 모델이 misaligned일 가능성을 전제로 설계한다고 밝힌다.

저자들은 이 결과가 도메인 특화 harness의 필요성을 없애지 않는다고 선을 긋는다. Prove2Me는 Lean 컴파일 가속이나 기존 인간 결과의 검색·재사용에서 여전히 효율을 높일 수 있다고 한다. 결론은 범용 도구(Git, 공유 DB)면 조율에 충분했고, 실험을 가능하게 한 것은 안전 경계라는 것이다.

## 왜 골랐나

AI 에이전트 개발 관점에서 직접 맞닿는다. 별도 메시징 없이 Git과 SQL 표만으로 대규모 멀티에이전트를 조율한 구조, 리드→captain→helper의 동적 재배치, 에이전트별 샌드박스·fail-closed 분류기 설계는 참고할 만하다. 또 에이전트가 난이도를 과소평가해 일찍 포기하는 경향은 에이전트 운영 설계의 시사점이다.

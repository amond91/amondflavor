## 한 줄 요약

Superlite는 Superpowers의 구조를 차용하되 사람의 반복 승인과 순차 실행을 없애, 명세를 넘기면 병렬 에이전트로 구현·테스트·리뷰까지 자율 수행하는 Claude Code 플러그인이다. 저자의 자체 벤치마크(단일 실행)에서 177개 비공개 테스트를 16.1분에 통과해 Superpowers 기본 구성(평균 33.6분) 대비 52% 단축됐다.

## 핵심

- 문제의식: 결과가 명확한 상황에서 Superpowers의 대기 시간은 기능당 8~12회의 사람 승인, 엄격한 순차 실행(에이전트 호출 21회가 한 줄), 작업마다의 리뷰·재리뷰(34분 빌드 중 약 12분), 전체 테스트 반복 실행, 핵심 경로의 Opus 하위 에이전트(Sonnet의 약 절반 속도)에서 발생했다고 한다.
- 승인 방식: 요청 규모에 따라 계획 절차를 달리하고(오타는 즉시 수정, 새 프로젝트는 최대 4개 질문 후 설계·계획 문서 하나), 사람이 계획을 한 번 승인하거나 AI 조율을 택해 스스로 결정하게 할 수 있다. AI 조율 시 각 결정의 선택·이유·오판 시 비용을 기록하며, 어느 쪽이든 사용자 없이 푸시나 병합은 하지 않는다.
- 병렬 구조: 계획은 작업 그래프(소유 파일, 입출력 인터페이스, 통과할 테스트)로 구성되고 파일을 공유하지 않는 독립 작업이 동시에 실행된다. Opus는 조율(코드 수정 불가), Sonnet은 주 구현과 리뷰, Haiku는 핵심 경로 밖의 작고 기계적인 작업, 별도 Opus 최종 리뷰어는 발견 사항만 반환하고, 수정은 3단계 수정 전담 에이전트가 맡는다.
- 규칙의 코드 강제: 프롬프트로 금지해도 조율자가 코드를 편집했기 때문에 훅으로 조율자의 코드 수정을 차단하고, 직접 실행한 pytest/npm test는 백그라운드로 전환하며, 프로세스 이름 기반 종료를 금지한다. 계획은 lint --stable을 통과해야 하고, 훅이 에이전트별 토큰·비용·시간을 기록해 예측에 쓰며 소프트 예산 70%에서 알림을 준다.
- 최신 벤치마크: 정적 사이트 생성기와 스프레드시트 엔진을 한 명세로 구현하는 프로젝트(비공개 테스트 177개)에서 16.1분, 177/177 통과, 에이전트 21개(최대 동시 18개), 최종 리뷰 30초, 사람에게 묻느라 멈춘 횟수 0이었다. Superpowers 기본 구성은 3회 평균 33.6분, 조율 구성은 23.5분이었고, 이전 Superlite 빌드(평균 26.9분)보다도 40% 짧다.
- 한계 표기: 최신 Superlite 수치는 단일 실행이고 비교 대상은 같은 머신의 이전 실행이라 저자 스스로 확정적 검증이 아닌 '유력한 신호'라고 밝힌다. 벤치마크는 저자가 직접 만든 하네스로 수행했다.
- 결론: 에이전트 워크플로가 느린 이유는 모델의 깊은 사고보다 순차 대기와 반복 승인일 수 있으므로, 인터페이스 경계로 작업을 나누고 독립 작업을 병렬화하며 기계적 단계는 스크립트로 옮기고 중요한 규칙은 코드로 강제하라고 권한다.

## 자세히

Superlite는 Superpowers의 플러그인 구조, 세션 시작 훅, 생명주기 스킬을 차용했다. 단계마다 사람이 관여하려면 Superpowers, 명세를 맡기고 자율 실행하려면 Superlite가 적합하다는 것이 저자의 구분이다. 두 플러그인은 스킬 이름을 공유하고 시작 시 모두 컨텍스트를 주입하므로 같은 세션에서 함께 활성화하면 안 된다.

초기 측정에서는 더 작은 sitegen 단독 과제(모듈 9개, 비공개 테스트 89개)에서 Superpowers 34.4분 대비 Superlite 8.8분이 걸렸고 둘 다 89개를 통과했다. Superpowers는 에이전트를 21회 순차 호출했고 Superlite는 총 10개를 최대 5개씩 동시 실행해 순차 호출 경로를 3단계로 줄였다. 177개 테스트 프로젝트에서의 이전 3회 비교는 Superpowers 평균 33.6분(21.2/31.9/47.6분, 편차 26.4분), Superlite 평균 25.1분(21.4/23.2/30.5분, 편차 9.1분)으로 Superlite가 더 빠르고 편차도 작았다.

당시 Superlite는 약 13분에 구현을 끝냈지만 리뷰·수정·조율자의 포그라운드 테스트에 10~18분이 더 들었다. 이를 줄이기 위해 조율자의 코드 수정 권한 제거, 모든 테스트의 백그라운드 실행, 단계별 수정 전담 에이전트 배정, 계획 수정 중에도 안정화된 작업의 구현 시작이라는 네 가지를 바꿔 16.1분에 도달했다.

사용법은 Claude Code, git, Python 3.10 이상, bash가 필요하며 `/plugin marketplace add iha2/superlite`, `/plugin install superlite@superlite-dev`로 설치한다. 실행 상태는 프로젝트의 `.superlite/`에서 progress.md(결정 기록·로그), test-summary.json(최신 테스트 결과), metrics.jsonl(에이전트별 시간·비용)로 확인한다. 필자는 후속 글에서 게이트, 에이전트 계층, 폐기한 아이디어를 더 깊게 다룬다고 예고했다.

## 왜 골랐나

AI 에이전트 개발 관점에서, 멀티 에이전트의 작업 그래프 분해, 모델 계층별 역할 배분, 프롬프트 대신 훅으로 규칙을 강제하는 설계, 에이전트별 비용·시간 계측과 같이 직접 참고할 만한 설계 패턴이 담겨 있다.

## 한 줄 요약

Lemma는 여러 사람이 같은 AI 팀원(에이전트)과 데이터·문서·워크플로·권한을 공유하며 일하게 해 주는 오픈소스 플랫폼이다. Claude Code, Codex, Cursor, OpenCode 같은 기존 코딩 에이전트로 앱·테이블·에이전트·워크플로·권한을 파일로 작성해 구성하며, Slack·Teams·WhatsApp·Telegram·이메일에서도 같은 권한으로 쓸 수 있다.

## 핵심

- 모든 작업 공간은 'pod'라는 단위로 구성된다. pod에는 Tables(행 단위 보안이 적용된 데이터), Files(마크다운 메모리·플레이북), Agents, Workflows, Functions, Permissions, Approvals, Connectors, Apps, Surfaces가 들어 있다.
- 팀의 수정과 피드백은 지속적인 지침으로 남고, 반복되는 순서는 워크플로로, 반복되는 판단은 에이전트 역할로 바뀐다고 한다. 원문은 이를 '하네스가 스스로 개선된다'고 표현한다. 공유 메모와 개인 메모는 구분된다.
- 워크플로는 일정, 웹훅, 테이블 행 변경, Slack·GitHub 이벤트로 시작된다. 사람의 승인이 필요한 단계에서는 멈추고, 결정이 나면 앱이나 Slack에서 재개된다. 며칠이 걸려도 된다.
- 권한은 사람과 에이전트에 같은 모델로 적용된다. pod 수준 역할, 테이블별 grant, 행별 접근, 위임 토큰, 승인 게이트가 있고, 앱·Slack·WhatsApp에서 같은 규칙이 적용된다.
- 모델은 기존 Claude Code·Codex·Cursor·OpenCode 로그인(Agent Host 경유), Lemma 제공 모델, OpenAI·Anthropic 호환 API, Ollama·LM Studio 로컬 모델 중에서 고를 수 있고, 에이전트마다 다르게 지정할 수 있다.
- 배포는 로컬(macOS 14+ Apple silicon 데스크톱 앱), Docker Compose 자체 서버, Lemma Cloud 중에서 고른다. Windows 설치 파일은 정식 배포되지 않는다. 핵심은 AGPL-3.0이고 SDK·CLI·스킬은 Apache-2.0이다.
- 고객 지원, 글쓰기, 팀 운영, 개인 생산성 등 10개 공개 pod 템플릿이 있다. pod 전체를 `lemma pod export/import`로 파일로 내보내고 가져올 수 있다. Python·TypeScript SDK(React 훅 25개 이상)도 있다.

## 자세히

사용 흐름은 이렇다. `uv tool install lemma-terminal`로 CLI를 설치하고 `lemma skills install`로 스킬을 코딩 에이전트에 넣는다. 그 뒤 빈 디렉터리에서 에이전트에게 업무를 설명하면 에이전트가 테이블·에이전트·워크플로·권한·앱을 파일로 쓰고 `lemma pod import`로 올린 다음 워크플로가 승인 단계에서 멈추는지 검증한다. 원문은 lemma-terminal이 Python 3.14를 요구하므로 pip 대신 uv를 쓰라고 안내한다.

원문은 '하네스'를 모델 주변의 도구·메모리·상태·루프·경계 전체로 정의한다. 코딩 에이전트가 한 사람·한 기기·한 세션용 하네스였다면, Lemma는 팀을 위한 공유·권한·상시 실행형 하네스라고 포지셔닝한다. Function은 같은 입력에 같은 출력을 내는 결정적 코드이고 에이전트가 도구로 호출하므로, 판단과 규칙을 분리할 수 있다는 설명이다.

README는 저장소가 816 커밋이고 backend(FastAPI), frontend, desktop(Tauri), CLI, SDK 등으로 나뉜다고 보여 준다. 원문 마지막 부분(개발 섹션)은 잘려 있다.

## 왜 골랐나

AI 에이전트 개발 관점에서, 에이전트 권한(역할·테이블·행 단위), 사람 승인 게이트, 코딩 에이전트가 스킬로 시스템 전체를 파일로 생성하는 방식을 참고할 만하다. 이는 원문에 직접 나온 설계다.

## 한 줄 요약

DeepSeek이 에이전트·RAG용 실시간 웹 접근 API인 Search API와 Fetch API를 공개했다. 둘 다 성공 요청 1,000건당 0.75달러이고, 토큰 수나 결과 수와 무관하게 과금한다.

## 핵심

- Search API(POST /v1/tools/search)는 DeepSeek 자체 검색 엔진으로 웹 검색 결과를 구조화해 반환한다. Fetch API(POST /v1/tools/fetch)는 단일 페이지의 title과 Markdown 본문을 반환한다. 둘 다 기존 DeepSeek API와 같은 Bearer 인증을 쓴다.
- Search는 query가 유니코드 1~128자여야 하고, count는 기본 10건에 1~50건까지 지정할 수 있다. site:, -site:, lang:, after:/before: 등 검색 연산자를 지원한다. 결과에는 snippet(UI용, 보통 100~200자)과 summary(모델용, 보통 600~800자)가 따로 들어 있다. rerank_score(0~3점, 1.5 이상이면 고품질)와 authority(0~4 등급)도 반환한다.
- 과금은 HTTP 200과 실제 결과(Search는 비어 있지 않은 results, Fetch는 페이지 본문)를 모두 충족할 때만 한다. 실패 요청, 빈 검색 결과, 타임아웃은 무료이며, count는 요청당 가격에 영향을 주지 않는다.
- 호출 한도는 Search와 Fetch가 계정당 각각 5 QPS이며 서로 독립적이다. 한도는 API 키가 아니라 계정 단위로 계산한다. Fetch에는 도메인별 QPS 한도도 있고, 어느 한도든 넘으면 429가 반환된다.
- Fetch는 보안 정책상 거부되면 403, 사용 가능한 본문을 가져오지 못하면 404를 반환한다. 404 원인에는 사이트 정책에 따른 차단, 미지원 콘텐츠 유형, 추출 가능한 Markdown 본문 부재 등이 있다. 408, 429, 5xx는 기다렸다 재시도하고, 402는 충전 후 재시도하며, 나머지 4xx는 요청을 고치지 않으면 재시도하지 않는다.
- DeepSeek Harness, Claude Code, Codex에서 DeepSeek API를 쓸 때 발생하는 서버 측 도구 호출은 이 두 API를 이용하며 현재 무료다. 2026년 11월 1일 베이징 시간 00:00부터 요청별 과금이 시작된다.

## 자세히

두 API는 읽기 전용 JSON API이며, 기본 주소는 https://api.deepseek.com이다. 요청에는 Authorization: Bearer 헤더와 Content-Type: application/json이 필요하다. 오류는 OpenAI 호환 형식을 따르고 param은 항상 null이다. 알 수 없는 요청 필드는 무시한다.

Search는 need_content가 기본 false라서 이 경우 content가 항상 빈 문자열이다. 원래 질문을 ori_question으로 넘겨 검색어 이해를 보완할 수 있고, localization에 IP 주소를 넘겨 결과를 지역화할 수 있다. 결과에는 사이트 이름과 아이콘, UTC 기준 RFC 3339 형식의 게시 시각도 들어 있으며 알 수 없는 값은 null이다.

Fetch의 대상 URL은 호스트가 있는 HTTP 또는 HTTPS 주소여야 하고, 최대 8,192자까지 허용하며, 사용자 이름이나 비밀번호를 포함할 수 없다. 페이지 수집은 대상 사이트의 가용성과 접근 정책에 영향을 받는다.

## 왜 골랐나

AI 에이전트 개발에 쓸 수 있는 웹 검색·페이지 수집 도구의 가격 구조(요청 단위 정액, 실패 무료)와 한도(5 QPS)를 확인할 수 있다. 특허·기술정책 자료나 희토류 가치사슬 관련 웹 정보를 에이전트가 수집하게 할 때 비용을 가늠하는 기준이 된다.
